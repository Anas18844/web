# لوحة التحكم — Dashboard

آخر تحديث: أغسطس ٢٠٢٦

## التشغيل — ٣ خطوات

### ١. شغّل الميجريشن

افتح **Supabase → SQL Editor** والصق محتوى الملف ده كامل:

```
web/supabase/migrations/004_dashboard.sql
```

بيعمل: جدول المستخدمين، جدول سجل المراجعة، وعمودين على `leads` للإضافة اليدوية.
آمن على جدول فيه بيانات، ومابيمسحش حاجة.

### ٢. اعمل الحسابات

من فولدر `web`:

```bash
npm run dashboard:user -- anas@example.com "أنس أحمد" admin
npm run dashboard:user -- sara@example.com "سارة محمد" team
```

هيسألك كلمة السر مرتين (مش بتظهر وإنت بتكتب، ومابتتسجّلش في تاريخ الأوامر)،
وهيطبعلك جملة SQL. الصقها في Supabase.

كلمة السر **١٢ حرف على الأقل** — الحساب ده بيقرا أرقام تليفونات طلبة قُصَّر.

لو شغّلت الأمر تاني لنفس الإيميل، بيغيّر كلمة السر بتاعته.

### ٣. ادخل

```
https://your-site.com/dashboard
```

مفيش متغيّر بيئة جديد. مفتاح توقيع الجلسات بيتولّد من مفتاح Supabase لو
`DASHBOARD_SESSION_SECRET` مش موجود — عشان مايبقاش فيه حاجة تانية تتنسي.

> ⚠️ نتيجة مقصودة: لما تغيّر مفتاح Supabase، كل الجلسات بتتقفل والكل بيسجّل دخول تاني.

### إزاي الأرقام متمنوعة فعلاً

**مش بالإخفاء في الواجهة.** عمود مخفي مش حاجز — الصف بيوصل المتصفح، وأي حد
يفتح Network tab يقراه.

الرقم **مابيخرجش من الداتابيز أصلاً** لحساب التيم:

- `listLeads(role)` بيبني الـ SELECT من الدور. أعمدة `phone` و`whatsapp` مش
  بتتطلب خالص لحساب التيم.
- فيه طبقة تانية بتحوّلهم لـ `null` — عشان لو حد كتب `select('*')` بعد ٦ شهور،
  يقع في الأمان مش في التسريب.
- البحث بالرقم مرفوض للتيم. لو سمحناه، يبقى عندهم أداة تقولهم «الرقم ده موجود
  ولا لأ» — وده بيرجّع نفس البيانات تخمين ورا تخمين.
- `getStats()` مابيقراش اسم ولا رقم ولا ملاحظة أصلاً. الإحصائيات مامحتاجاهمش.

الواتساب متعامل معاه زي التليفون. هو رقم تليفون، وكونه في عمود تاني مابيغيّرش ده.

## سجل المراجعة

كل تعديل وحذف بيتسجّل في `dashboard_audit`: مين عمله، وإمتى، و**الصف كامل قبل
التغيير**. الجزء الأخير ده هو المهم — من غيره، صف متمسوح مالوش أي أثر يفرّقه عن
صف ماكانش موجود.

الحذف محتاج تكتب كلمة **«احذف»** بإيدك. مش عشان الشكل: الحذف بيدمّر السجل الوحيد
لطالب طلب مساعدة.

```sql
-- مين عمل إيه آخر أسبوع
select at, actor_email, actor_role, action, lead_id
from dashboard_audit
where at > now() - interval '7 days'
order by at desc;
```

## الأرقام والرسوم

الألوان مش مختارة بالذوق. الدهبي والسماوي بتوع الهوية (`#CBA352` / `#48C8D5`)
فاتحين أكتر من اللازم على خلفية كحلي غامق — قياسهم `L 0.74` و`0.77` والنطاق
الآمن `0.48–0.67`. فضلنا نفس درجة اللون وغمّقنا الإضاءة، وبعدين اتفحصوا:

```
#B58E36 + #12A0B2  على #0A1526  →  كل الفحوصات نجحت
(عمى ألوان ΔE 14.8 · رؤية عادية 18.6 · تباين ≥ 3:1)
```

- **مصدر المعرفة** = ألوان متساوية (لون واحد). الترتيب مالوش معنى، وطول العمود
  بيقول الكمية بالفعل.
- **حالة المتابعة** = تدرّج لون واحد من الفاتح للغامق. الترتيب هنا **له** معنى
  (جديد ← اتكلمنا ← حجز ← اشترك)، فاللون بيقوله.

### حاجات الرسوم بترفض تقولها

- **مفيش نسبة مئوية لو الأسبوع اللي فات أقل من ١٠.** ٣ بقوا ٦ = «+٣»، مش
  «+١٠٠٪». لوحة بتقول +١٠٠٪ على أساس ٣ قالت كذبة ممكن حد ياخد قرار بيها.
- **المحور بيبدأ من صفر** دايمًا. محور مقصوص بيحوّل أسبوعين ثابتين لجبل.
- **في آخر صفحة التحليلات فيه قايمة بحدود كل رقم** — إيه اللي مش محسوب فيه
  وليه. ده الجزء اللي أغلب اللوحات بتسيبه، وهو اللي بيمنع قرار غلط.

## الاختبار

```bash
npm run verify:auth
```

بيختبر الحاجات اللي اللوحة قايمة عليها — مش بيفترضها:

- كلمة السر بتتخزّن متملّحة، والنص الأصلي مش موجود في المخزّن
- **تزوير الكوكيز**: تغيير الدور لـ `admin` بيتـرفض (التوقيع بيبطل)
- إعادة التوقيع بمفتاح متخمّن بتترفض
- الجلسة المنتهية بترفض، والتوكن المقطوع مابيرميش استثناء
- الـ SELECT بتاع التيم مافيهوش `phone` ولا `whatsapp` (بيقرا الكود نفسه)
- كل أكشن بينادي `requireAdmin` / `requireUser`

٢٦ فحص. لو أي واحد وقع، الحاجز اتكسر.

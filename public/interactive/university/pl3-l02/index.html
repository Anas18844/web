يعني إيه Type System؟

الـ Type system مجموعة قواعد بتدي نوع لكل حاجة في اللغة: variables، و expressions، و functions.

بيعمل 3 حاجات

  1. Assigns Types: يربط الكود بالأنواع، والعمليات بتتحدد حسب النوع.
  2. Prevents Errors: يمسك العمليات الغلط بدري، زي جمع نص على مصفوفة.
  3. Enables Optimizations: الـ compiler بيعمل كود أسرع، لأنه عارف شكل الذاكرة.

المسار: Code → Type System Rules → Valid/Invalid → Optimized Code

Static vs Dynamic: إمتى بيتفحص النوع؟

السؤال الوحيد: الفحص بيحصل قبل التشغيل ولا أثناء التشغيل؟

Static: compile-time
int x = "hello"; // ERROR
  • الـ compiler بيمسك الغلط بدري.
  • أسرع في التنفيذ.
  • Strong guarantees.
  • أمثلة: Rust و Java و C++.
Dynamic: runtime
x = "hello"
x = 5  # valid
  • الأخطاء بتظهر وقت التشغيل.
  • Potential overhead.
  • Flexibility over safety.
  • أمثلة: Python و JavaScript و Ruby.

Strong vs Weak: بيحوّل لوحده؟

السؤال هنا مختلف: هل اللغة بتحوّل نوع لنوع لوحدها (implicit coercion)؟

Strong
  • مفيش implicit coercion.
  • لازم explicit conversion.
  • بيمنع الأخطاء العرضية.
  • Rust و Java و Python.
Weak
  • فيه implicit coercion.
  • بيحوّل لوحده.
  • Flexible بس ممكن يعمل bugs.
  • JavaScript و PHP و C.

المثال اللي الدكتور حاطه

// Subtraction
console.log("5" - 2); // 3     string "5" -> number 5
// Addition
console.log("5" + 2); // "52"  number 2 -> string "2"
  1. - شغالة على أرقام بس، فالـ "5" بتتحول لرقم: 5 - 2 = 3.
  2. + مع نص بتعمل دمج، فالـ 2 بتتحول لنص: "52".
فخ: Python Dynamic و Strong. يعني static/dynamic سؤال غير strong/weak.
معمل: JavaScript حقيقية بتشتغل قدامك

Polymorphism 1: Parametric

Polymorphism معناها شكل واحد يتعامل مع أنواع كتير. وفيه 3 أنواع.

Parametric: كود واحد لكل الأنواع

بنكتب الكود generic، و T هو type variable (مكان فاضي للنوع)، والـ compiler بيحط النوع الحقيقي.

class Box<T> {
    T value;
    Box(T v) { value = v; }
    T getValue() { return value; }
}
Box<Integer> intBox = new Box<Integer>(123);
Box<String> stringBox = new Box<String>("hello");
System.out.println(intBox.getValue());    // 123
System.out.println(stringBox.getValue()); // hello
نفس الكلاس. و T = Integer مرة، و T = String مرة.

الفوايد: code reuse، و compile-time type safety، و performance benefits through inlining.

Polymorphism 2: Ad-hoc

نفس الاسم، بس تنفيذ مختلف حسب أنواع الـ arguments. ده الـ overloading.

class Calculator {
    int add(int a, int b) { return a + b; }
    double add(double a, double b) { return a + b; }
}
Calculator calc = new Calculator();
int result1 = calc.add(5, 10);      // calls int add
double result2 = calc.add(3.5, 2.1); // calls double add
  1. الـ compiler بيختار التنفيذ في compile-time.
  2. التمييز بأنواع الـ arguments، مش بنوع الـ return.
فخ: لو دالتين نفس الاسم ونفس الـ arguments ومختلفين في الـ return type بس، ده مش overloading صح.

Polymorphism 3: Subtype

قيمة من نوع فرعي (subtype) تتحط مكان نوع عام (supertype). وبيتعمل بالـ inheritance أو الـ interface.

class Animal {
    void speak() { System.out.println("Animal makes a sound"); }
}
class Dog extends Animal {
    @Override void speak() { System.out.println("Woof"); }
}
class Cat extends Animal {
    @Override void speak() { System.out.println("Meow"); }
}
Animal myDog = new Dog();
Animal myCat = new Cat();
myDog.speak(); // Woof
myCat.speak(); // Meow
  1. myDog نوعه المكتوب Animal.
  2. بس الـ object الحقيقي Dog.
  3. النتيجة Woof، لأن التنفيذ بيتحدد بنوع الـ object. ده dynamic dispatch.

الفوايد: code reuse، و method overriding، و dynamic dispatch، و flexibility.

المشكلة: fragile base class problem: تغيير في الـ superclass ممكن يأثر على كل الـ subclasses.

Type Inference: Hindley-Milner

Type inference: في لغة static، الـ compiler بيستنتج النوع لوحده من غير ما تكتبه.

Hindley-Milner: الخوارزمية الأساسية. بتستنتج أعم نوع (most general type)، حتى الـ polymorphic. ومستخدمة في ML و Haskell.

square x = x * x
-- inferred: Num a => a -> a

الاستنتاج خطوة خطوة

  1. x نوعه مجهول: a.
  2. * شغالة على أرقام: يبقى Num a.
  3. الناتج نفس النوع: a -> a.

الفوايد: كود أقصر، و annotations أقل، و polymorphic functions، ومن غير ما تخسر الـ static checking.

فخ: type inference مش dynamic typing. النوع معروف في الـ compile-time.

Dependent Types

عادةً النوع حاجة والقيمة حاجة. في Dependent types، النوع بيعتمد على قيمة.

يعني بتخلط الـ type level بالـ term level. ومثال اللغات في الـ outline: Idris و Coq.

  • بتعمل compile-time verification لحاجات كانت محتاجة runtime checks أو formal proofs.
  • Precise specifications.
  • بتلغي أنواع كاملة من الـ bugs.
بتيجي في Research Question: ليه مهمة في safety-critical systems؟ لأنها بتثبت صحة خصائص البرنامج في الـ compile-time.

دراسة حالة: Rust Ownership

Rust: Strong و Static. الأنواع بتتفحص بدقة، و no implicit type conversions.

وبتضمن memory safety من غير garbage collector: مفيش null pointer dereferences، وبتمنع data races و use-after-free.

الكود اللي الدكتور بيحبه

fn main() {
    let s1 = String::from("hello"); // s1 owns the data
    let s2 = s1;                    // ownership moved to s2
    println!("{}", s2);             // valid: hello
    println!("{}", s1);             // COMPILE-TIME ERROR
}
معمل: امشي مع الكود سطر سطر
القاعدة

بعد let s2 = s1; الـ ownership اتنقل (Move semantics). فـ s1 مبقاش valid، واستخدامه compile-time error.

فخ: الغلط في آخر سطر بس، مش في let s2 = s1;. وهو compile-time مش runtime.
